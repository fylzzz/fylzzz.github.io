Amp'd was produced by a team of 2nd and 3rd year Griffith University Game Design and Production students for Games Studio 2026. The team was tasked with creating a musical-themed arena shooter, inspired by games such as Quake and Splatoon.

Individual Contribution

My role in this project was primarily network programming and designing/composing gameplay SFX and the main gameplay theme. Coming into the project after the prototyping phase, I was challenged with working inside a pre-existing codebase to implement a robust online networking solution, helping take the LAN-focused prototype to a fully playable experience.

Deliverables

  • Online multiplayer framework
  • SFX for 4 instrument-themed guns
  • Main musical theme for the arena

Designing Online Multiplayer

Initially, Amp'd was pitched as a LAN-multiplayer focused game, and during the prototyping phase was designed and programmed with this assumption in mind. I joined the project after this prototype was completed, however around this time the team was discussing how to better playtest the game, considering the limitation that players needed to be on the same network to play together. This led to my decision to focus my contribution on designing and implementing a complete online multiplayer system, allowing players to host and join sessions from anywhere at any time. In my time working on the project, I scoped, designed and shipped lobby hosting/management and server browser systems, while maintaining the pre-existing networked gameplay functions.

The Solution

Since the project was already in Unreal Engine, after some research I chose to utilise Epic Online Services (with the EOS Integration Kit plugin: https://github.com/betidestudio/EOSIntegrationKit) While I would have liked to build the system from scratch, using a plugin was the best choice considering the scope and timeframe of the project. Using EOS also allowed me to simply build the lobby management and server browser systems on top of the exisiting netcode, without having to change any gameplay features by replacing LAN-based blueprint nodes with their EOS counterparts.

One of the main challenges I faced with developing the system however, was storing the server data to allow players to safely leave/destroy lobbies. Players join a lobby from the main menu scene, and are then loaded into the map scene for the pre-game lobby and gameplay, so I had to figure out a solution for saving data such as the lobby id/name (required for the Destroy Lobby node,) without it being erased between scenes. This problem took quite a while to solve until I came across a little-used GameInstance class in UE5, which exists locally for the player, and is not cleared when changing scenes, making it perfect for storing this kind of data
